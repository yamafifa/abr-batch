# v1：素直に書いた遅い版

[src/import-naive.ts](../src/import-naive.ts)

- CSV を丸ごとメモリに読み込んでから、Prisma の `create` で 1 件ずつ INSERT します

## 実行コマンド

準備（DB の起動、データのダウンロード、テーブル作成）は、README の「[動かし方](../README.md#動かし方)」を参照してください。

```bash
npm run import:naive -- --limit 10000   # 先頭の 10,000 件だけ入れる
```

- `--limit` を付けないと全件を入れます。5 時間ほどかかるので、件数を区切って試してください
- 実行前に、テーブルの中身をすべて消します

## 計測結果

| 件数 | 時間 | 速度 | 最大メモリ |
|---|---|---|---|
| 1,000 | 23.26 秒 | 43 件/秒 | 1,337 MB |
| 10,000 | 114.06 秒 | 88 件/秒 | 1,453 MB |

- 時間には CSV 全体を読み込む十数秒が含まれるので、件数が少ないほど速度の数字が下がります

## 処理時間の見込み（全件）

- この速さのまま全件（1,752,573 件）を入れると、5 時間ほどかかる計算です
- 全件は測っていません。README の結果のまとめで他の版と比べている「約 5 時間」は、この計算の値です

## 遅い原因

- 1 件ごとに DB と往復するため、1 件あたり約 10 ミリ秒かかります（上の 2 回の差から計算）
- CSV（約 150 MB）を丸ごと読み込むため、件数が少なくてもメモリを 1.3 GB 以上使います
