# v5：ストリーミング処理 + まとめて INSERT（Prisma を使わない）

[src/import-v5.ts](../src/import-v5.ts)

- v2 と同じく、CSV を少しずつ読みながら、まとめて INSERT します
- v2 との違いは、SQL の作り方と送り方だけです
  - SQL は自分で組み立てます（`INSERT INTO ... VALUES (?, ...), (?, ...), ...`）
  - mariadb ドライバーの `query` で送ります。ドライバーが値を SQL に埋め込んで、1 回で送る方式です
- v4 を作ったあとに、v2 が遅い原因を確かめるために作りました（下の「v2 が遅い原因」を参照）

## 実行コマンド

準備（DB の起動、データのダウンロード、テーブル作成）は、README の「[動かし方](../README.md#動かし方)」を参照してください。

```bash
npm run import:v5                                         # 全件を 1,000 件ずつ入れる
NODE_OPTIONS=--max-old-space-size=512 npm run import:v5   # 計測と同じく、ヒープ上限を 512 MB にして入れる
npm run import:v5 -- --batch 2000                         # 1 回にまとめる件数を変える
```

- ヒープ上限は、Node.js が JavaScript のデータ用に使えるメモリの上限です
- `--limit 件数` を付けると、先頭からその件数だけ入れます
- 実行前に、テーブルの中身をすべて消します（`TRUNCATE`）

## 計測結果（全件 1,752,573 件、ヒープ上限 512 MB）

| まとめる件数 | 時間 | 速度 | 最大メモリ | MySQL の中の INSERT の時間 |
|---|---|---|---|---|
| 500 件 | 61.78 秒 | 28,367 件/秒 | 137 MB | 45.73 秒（3,506 回） |
| **1,000 件** | **50.97 秒** | **34,383 件/秒** | **136 MB** | 33.96 秒（1,753 回） |
| 2,000 件 | 44.69 秒 | 39,219 件/秒 | 146 MB | 27.32 秒（877 回） |
| 3,000 件 | 43.90 秒 | 39,919 件/秒 | 149 MB | 26.83 秒（585 回） |
| 5,000 件 | 44.04 秒 | 39,795 件/秒 | 164 MB | 26.67 秒（351 回） |

- 1,000 件ずつで、v2（415.26 秒）の約 8 倍の速さです
- MySQL の中の時間は、performance_schema（MySQL が SQL ごとの実行時間を記録する仕組み）で測りました
- どの件数でも、取り込んだテーブルのチェックサムは v2・v3 と一致しました（967527444）

## 1 回にまとめる件数の比較

- v5 は、まとめる件数を増やすと速くなりました。ただし 2,000 件から先は、ほとんど変わりません
- v2 では、1,000 件より増やすとわずかに遅くなりました（[v2 の説明](v2-stream.md)を参照）。v2 で頭打ちになったのは、DB との往復ではなく、下の「Node.js 側の時間」が効いていたためと考えられます
- メモリは、まとめる件数を変えてもほとんど変わりませんでした（136〜164 MB）
- 比べやすさのため、README の結果のまとめでは v2 と同じ 1,000 件ずつの値を使っています

## v2 が遅い原因

v2 と v5 は、どちらも 1,000 件ずつ INSERT します。全件を入れたときの時間を、MySQL の中と外に分けて比べました。v2 は、v5 と同じ日に performance_schema を有効にして測り直した値です。

| | v2（Prisma の `createMany`） | v5（mariadb ドライバーの `query`） |
|---|---|---|
| 全体の時間 | 419.52 秒 | 50.97 秒 |
| MySQL の中：INSERT の実行 | 35.55 秒（1,754 回） | 33.96 秒（1,753 回） |
| MySQL の中：SQL の準備と後片付け | 11.92 秒（各 1,754 回） | なし |
| MySQL の外（全体 − MySQL の中） | 約 372 秒 | 約 17 秒 |

- v2 の INSERT の実行回数 1,754 回には、最初の `TRUNCATE` の 1 回が含まれます
- **INSERT そのものの重さは、ほぼ同じです。** MySQL がデータを書き込む仕事量は変わりません
- **v2 は、1,000 件ごとに SQL の準備と後片付けもしています。** Prisma がプリペアドステートメント（SQL の形を先に MySQL に渡し、値を後から送る方式）で送り、準備した SQL を使い回していないためです
- **差のほとんどは MySQL の外、つまり Node.js 側にあります**（約 372 秒と約 17 秒）

分かっていないこと：

- v2 の Node.js 側の約 372 秒が、Prisma のどの処理に使われているかは、まだ突き止めていません。突き止めるには CPU プロファイル（どの関数に時間を使ったかの記録）を取る必要があります
- MySQL のプリペアドステートメントで使える値の数の上限は 65,535 個です。v2 は 1 回あたり 22,000 個（1,000 件 × 22 列）なので、上限には当たっていません。Prisma が SQL を分けて送ってもいませんでした
